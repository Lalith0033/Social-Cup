# Social Cup - Phase 1 Database Schema

> Status: Initial schema design
>
> PostgreSQL 16 is the authoritative persistence layer. This document maps
> directly to the rules in `PRODUCT_AND_BUSINESS_RULES.md`.

## 1. Conventions

- PostgreSQL 16.
- UUID primary keys generated by the application or `gen_random_uuid()`.
- `timestamptz` for all timestamps; server UTC is authoritative.
- Integer cents for money.
- Positive integer columns for credit costs and credit amounts where required.
- Enum-like values use PostgreSQL `CHECK` constraints or PostgreSQL enums only
  when the state is stable.
- Financial and audit records are append-only.
- Soft deletion/anonymization is preferred over deleting financial history.

## 2. Identity and Access

### `users`

```text
id                  uuid primary key
status              text not null: REGISTERED, ACTIVE, SUSPENDED, DELETED
role                text not null: MEMBER, ADMIN
display_name        text nullable
email               text nullable
profile_photo_url   text nullable
home_neighbourhood  text nullable
preferences         jsonb not null default '[]'
created_at          timestamptz not null
updated_at          timestamptz not null
deleted_at          timestamptz nullable
```

`email` and profile data are scrubbed during account deletion. Historical rows
remain linked by `user_id` for accounting.

### `user_identities`

```text
id                  uuid primary key
user_id             uuid not null references users(id)
provider            text not null: PASSWORD, GOOGLE, APPLE
provider_subject    text not null
password_hash       text nullable
email_verified_at   timestamptz nullable
created_at          timestamptz not null
unique(provider, provider_subject)
```

Password rows use Argon2id. OAuth identities do not store provider secrets.

### `refresh_tokens`

```text
id                  uuid primary key
user_id             uuid not null references users(id)
token_hash          char(64) not null unique
expires_at          timestamptz not null
revoked_at          timestamptz nullable
created_at          timestamptz not null
```

### `admin_two_factor_challenges`

```text
id                  uuid primary key
user_id             uuid not null references users(id)
challenge_hash      char(64) not null unique
expires_at          timestamptz not null
used_at             timestamptz nullable
created_at          timestamptz not null
```

The exact second-factor provider remains an implementation decision, but the
admin flow must not be considered complete without it.

## 3. Café and Menu Data

### `neighbourhoods`

```text
id                  uuid primary key
name                text not null unique
```

### `cafes`

```text
id                  uuid primary key
name                text not null
address             text not null
latitude            numeric(9,6) not null
longitude           numeric(9,6) not null
neighbourhood_id    uuid not null references neighbourhoods(id)
opening_hours       jsonb not null
vibe_tags           jsonb not null default '[]'
active              boolean not null default true
payout_rate_cents   integer not null check (payout_rate_cents >= 0)
pin_hash            text not null
pin_version         integer not null default 1 check (pin_version > 0)
created_at          timestamptz not null
updated_at          timestamptz not null
```

`pin_hash` uses Argon2id. Coordinates support the application-level Haversine
calculation and are not a PostGIS dependency.

### `cafe_photos`

```text
id                  uuid primary key
cafe_id             uuid not null references cafes(id)
storage_key         text not null
sort_order          integer not null check (sort_order between 1 and 5)
created_at          timestamptz not null
unique(cafe_id, sort_order)
```

### `drinks`

```text
id                  uuid primary key
cafe_id             uuid not null references cafes(id)
name                text not null
description         text not null
retail_price_cents  integer not null check (retail_price_cents >= 0)
credit_cost         integer not null check (credit_cost > 0)
active              boolean not null default true
created_at          timestamptz not null
updated_at          timestamptz not null
```

Inactive drinks remain available in historical snapshots but cannot be newly
redeemed.

## 4. Billing and Credits

### `subscriptions`

```text
id                         uuid primary key
user_id                    uuid not null references users(id)
stripe_customer_id         text not null unique
stripe_subscription_id     text not null unique
status                     text not null:
                           NONE, ACTIVE, PAST_DUE, CANCELING, UNPAID, CANCELED
current_period_start       timestamptz nullable
current_period_end         timestamptz nullable
cancel_at_period_end       boolean not null default false
created_at                 timestamptz not null
updated_at                 timestamptz not null
```

There is one current subscription record per member. State transitions are
validated in the API and database writes.

### `billing_periods`

```text
id                         uuid primary key
user_id                    uuid not null references users(id)
stripe_invoice_id          text not null unique
period_start               timestamptz not null
period_end                 timestamptz not null
credits_granted            integer not null check (credits_granted = 30)
created_at                 timestamptz not null
```

### `user_credit_balances`

```text
user_id                    uuid primary key references users(id)
current_balance            integer not null check (current_balance >= 0)
updated_at                 timestamptz not null
```

This row is locked with `SELECT ... FOR UPDATE` before a redemption deduction
or restoration.

### `credit_ledger_entries`

```text
id                         uuid primary key
user_id                    uuid not null references users(id)
billing_period_id          uuid nullable references billing_periods(id)
amount                     integer not null
entry_type                 text not null:
                           GRANT_BILLING, DEDUCT_REDEMPTION, RESTORE_VOID
reference_id               uuid nullable
idempotency_key            text not null unique
created_at                 timestamptz not null
```

Positive entries grant or restore credits. Redemption entries are negative.
The operational balance must equal the sum of ledger entries for the active
accounting view.

### `stripe_events`

```text
id                         uuid primary key
stripe_event_id             text not null unique
event_type                  text not null
payload                     jsonb not null
processed_at                timestamptz nullable
created_at                  timestamptz not null
```

This table prevents webhook retries from issuing duplicate grants.

## 5. Barista Device Trust

### `barista_device_sessions`

```text
id                         uuid primary key
cafe_id                    uuid not null references cafes(id)
pin_version                integer not null
session_token_hash         char(64) not null unique
expires_at                 timestamptz not null
revoked_at                 timestamptz nullable
created_at                 timestamptz not null
```

The raw session token is sent only in an HTTP-only secure cookie. A session is
invalid when its stored `pin_version` differs from `cafes.pin_version`.

### `barista_pin_attempts`

```text
id                         uuid primary key
cafe_id                    uuid not null references cafes(id)
ip_address                 inet not null
succeeded                  boolean not null
created_at                 timestamptz not null
```

Lockout is derived from the append-only log: more than five failures for the
same `(ip_address, cafe_id)` within 15 minutes causes a 30-minute lockout.
Successful authentication resets the effective failure count.

## 6. Redemption

### `redemption_tokens`

```text
id                         uuid primary key
user_id                    uuid not null references users(id)
cafe_id                    uuid not null references cafes(id)
drink_id                   uuid not null references drinks(id)
token_hash                 char(64) not null unique
backup_code_hash           char(64) not null unique
credit_cost_snapshot       integer not null check (credit_cost_snapshot > 0)
status                     text not null: PENDING, REDEEMED, EXPIRED, SUPERSEDED
expires_at                 timestamptz not null
created_at                 timestamptz not null
redeemed_at                timestamptz nullable
```

Only one pending token is allowed per user. This is enforced with a partial
unique index:

```sql
CREATE UNIQUE INDEX redemption_tokens_one_pending_per_user
ON redemption_tokens (user_id)
WHERE status = 'PENDING';
```

The API stores only SHA-256 hashes of the QR token and salted backup code.

### `redemptions`

```text
id                         uuid primary key
token_id                   uuid not null unique references redemption_tokens(id)
user_id                    uuid not null references users(id)
cafe_id                    uuid not null references cafes(id)
drink_id                   uuid not null references drinks(id)
billing_period_id          uuid nullable references billing_periods(id)
cafe_name_snapshot         text not null
drink_name_snapshot        text not null
retail_price_snapshot_cents integer not null
credit_cost_snapshot       integer not null
payout_rate_snapshot_cents integer not null
cafe_payout_amount_cents   integer not null
platform_margin_amount_cents integer not null
status                     text not null: COMPLETED, VOIDED
idempotency_key             uuid not null unique
redeemed_at                timestamptz not null
voided_at                  timestamptz nullable
void_reason                 text nullable
voided_by_user_id           uuid nullable references users(id)
```

All financial values are captured at redemption time and never recalculated
from current café or drink records.

## 7. Ratings

### `ratings`

```text
id                         uuid primary key
user_id                    uuid not null references users(id)
cafe_id                    uuid not null references cafes(id)
drink_id                   uuid not null references drinks(id)
redemption_id              uuid nullable references redemptions(id)
stars                      integer not null check (stars between 1 and 5)
note                       text nullable
verified_redemption        boolean not null default false
hidden                     boolean not null default false
created_at                 timestamptz not null
updated_at                 timestamptz not null
unique(user_id, drink_id)
```

The API rejects notes longer than 140 characters and sanitizes output. Hidden
ratings remain stored but are excluded from public aggregates.

## 8. Payouts and Adjustments

### `payout_batches`

```text
id                         uuid primary key
cafe_id                    uuid not null references cafes(id)
period_start               timestamptz not null
period_end                 timestamptz not null
status                     text not null: DRAFT, APPROVED, PAID
wire_reference             text nullable
payment_date               date nullable
created_at                 timestamptz not null
approved_at                timestamptz nullable
paid_at                    timestamptz nullable
approved_by_user_id        uuid nullable references users(id)
paid_by_user_id            uuid nullable references users(id)
```

`APPROVED -> PAID` requires both `wire_reference` and `payment_date`. The
transition is one-way.

### `payout_batch_items`

```text
id                         uuid primary key
batch_id                   uuid not null references payout_batches(id)
redemption_id              uuid not null unique references redemptions(id)
amount_cents               integer not null
created_at                 timestamptz not null
```

### `cafe_payout_adjustments`

```text
id                         uuid primary key
cafe_id                    uuid not null references cafes(id)
source_redemption_id       uuid not null references redemptions(id)
target_batch_id            uuid nullable references payout_batches(id)
amount_cents               integer not null
reason                     text not null
created_at                 timestamptz not null
created_by_user_id          uuid not null references users(id)
```

Post-settlement voids create a negative future adjustment and do not modify
the paid statement.

## 9. Audit and Invariants

### `audit_events`

```text
id                         uuid primary key
actor_user_id              uuid nullable references users(id)
actor_type                 text not null: MEMBER, BARISTA, ADMIN, SYSTEM
action                     text not null
entity_type                text not null
entity_id                  uuid nullable
metadata                   jsonb not null default '{}'
created_at                 timestamptz not null
```

Important invariants are enforced through database constraints and transaction
tests:

1. No balance is negative.
2. Every credit mutation has one unique ledger idempotency key.
3. At most one pending token exists per member.
4. A token can produce at most one redemption.
5. A redemption's snapshots are immutable.
6. A rating is unique per user and drink.
7. Paid payout batches cannot be edited or reverted.
8. A void records its reason and administrator.
9. Stripe events and scan requests are idempotent.
